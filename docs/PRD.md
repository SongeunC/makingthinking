# 토론 수업 도우미 PRD

가치수직선을 중심으로 한 교실 토론용 웹앱. 개발은 Claude Code로 진행한다.

표기 규칙: 본문은 모두 사용자와 합의한 내용이다. 합의하지 않았고 작성자가 붙인 추정은 "11. 추정으로 채운 항목"에 따로 모았다. Claude Code는 이 항목을 임의로 바꾸지 말고, 막히면 사용자에게 물어볼 것.

---

## 1. 개요

교사가 방을 만들고 주제를 입력하면 학생들이 수직선 위에서 자기 입장을 고르고 이유를 쓴다. 결과는 교사 화면에서 이름 칩을 눌러 한 명씩, 또는 모두 보기로 확인한다. 이어서 "다시 생각"으로 2차 선택을 받아 생각이 얼마나 바뀌었는지 비교한다. 이후 의견 카드(패들렛형)와 워드클라우드로 토론을 정리한다.

## 2. 사용자와 사용 환경

- 사용자: 교사 1명(본인 수업 전용), 학생 25~30명
- 동시에 열리는 방: 1개
- 학생 기기: 크롬북, 아이패드, 스마트폰 순. 터치와 마우스 모두 지원하고, 스마트폰의 좁은 화면에서도 눈금을 누르기 쉬워야 한다.
- 교사 화면: 교실 TV나 전자칠판에 띄워 사용한다.

## 3. 기술 구성

- 배포: GitHub Pages
- 인증: Firebase Authentication (교사 구글 로그인)
- 저장과 실시간 동기화: Firebase Firestore
- 학생 응답은 Firebase에만 저장한다. GitHub에는 올리지 않는다.

## 4. 개발 단계

1차 개발
- 교사 구글 로그인
- 방 만들기, 접속 코드와 QR
- 학생 입장
- 가치수직선 (1차, 2차)
- 이름 칩, 모두 보기
- 이름 숨기기
- 이동 표시
- 방 저장과 다시 열기

2차 개발
- 의견 카드(패들렛형)와 반응
- 워드클라우드

1차를 먼저 완성해 실제 수업에서 써 본 뒤 2차를 진행한다.

## 5. 입장과 방 관리 (1차)

### 5-1. 교사
- 구글 로그인 후에만 방을 만들 수 있다.
- 내가 만든 방 목록을 볼 수 있다.
- 방을 만들 때 주제와 수직선 양 끝 라벨을 입력한다.
  - 양 끝 라벨 기본값: 왼쪽 "매우 찬성", 오른쪽 "매우 반대". 교사가 바꿀 수 있다.
- 방이 만들어지면 접속 코드(6자리)와 QR이 표시된다.
- 방을 삭제하면 그 방의 학생 이름, 선택, 이유, 의견 카드가 함께 삭제된다.
- 방 화면에서 참여자 한 명을 골라 삭제할 수 있다(중복 참여자 정리용).
- 저장된 방을 다시 열면 수업 때 모습 그대로 보인다. 1차·2차 비교, 이동 표시, 이름 숨기기도 그대로 동작한다.

### 5-2. 학생
- 접속 코드를 입력하고, 이름을 입력해서 입장한다. 별도 로그인은 없다.
- 받는 정보는 이름뿐이다. 반이나 번호는 받지 않는다.
- 같은 이름이 이미 있으면 뒤에 번호를 자동으로 붙인다(김민준, 김민준2).
- 새로고침이나 튕김 후 같은 기기에서 다시 열면 원래 참여자(이름·선택·카드)로 이어서 들어간다.
  - 2026-10-15 변경. 처음에는 "다시 들어오면 새 참여자"였으나, 실제 수업에서 의견 카드로 넘어갈 때 튕김이 잦아 바꿨다.
- 한 기기를 여러 학생이 번갈아 쓸 때를 위해 학생 화면에 "다른 이름으로 새로 들어가기"를 둔다.

### 5-3. 데이터 보관
- 교사가 직접 삭제할 때까지 보관한다. 자동 삭제는 없다.

## 6. 가치수직선 (1차 개발)

### 6-1. 수직선
- 눈금 방식이다. 가운데를 0으로 두고 좌우 5칸씩, -5부터 +5까지 11칸.
- 연속 선택(아무 곳이나 클릭)은 쓰지 않는다.

### 6-2. 학생 화면
- 자기 이름과 자기 선택 화면만 나온다. 다른 학생의 이름, 선택, 이유는 보이지 않는다.
- 학생은 눈금 한 칸을 고르고 이유를 쓴 뒤 제출한다.
- 이유는 필수다. 빈칸이면 제출할 수 없다. 글자 수 제한은 없다.
- 제출하면 잠긴다. 선택을 바꾸려면 교사가 "다시 생각"을 눌러 2차로 넘어가야 한다.
- 제출 결과는 학생끼리 바로 보이지 않는다.
- 2차 때는 자기 1차 선택 위치와 이유가 참고용으로 함께 보인다.

### 6-3. 교사 화면: 이름 칩
- 입장한 학생의 이름 칩이 화면 위쪽에 한 칸에 하나씩 뜬다. 수업이 진행되는 내내 계속 떠 있다.
- 이 칩 목록은 교사 화면에만 보인다.
- 칩을 누르면 그 학생이 선택한 지점이 수직선에 표시되고, 이유도 함께 볼 수 있다.
- 여러 칩을 동시에 선택할 수 있다. 칩을 누를 때마다 화살표가 하나씩 추가되고, 같은 칩을 다시 누르면 해제된다.
- "모두 보기" 버튼은 전체 칩을 한 번에 선택한다.
- 학생 화살표를 직접 눌러도 칩을 누른 것과 같이 동작한다.

### 6-4. 화살표 표시
- 화살표는 이름 상자에서 수직선 쪽으로 뻗는 모양이다. 화살표 안에 이름이 들어간다.
- 이유 상자는 이름 상자의 바깥쪽(수직선에서 먼 쪽)에 붙는다.
- "모두 보기"에서는 이름 화살표만 보이고, 학생을 선택하면 그 화살표에 이유 상자가 붙는다.
- 같은 칸에 여러 명이 있으면 수직선에서 멀어지는 방향으로 화살표를 차곡차곡 쌓는다.
- 이유 상자가 여러 개 열려도 서로 가리지 않게 배치한다.
- 이유가 길면 접어서 보여준다.
- 1차 화살표는 수직선 아래쪽에 표시된다(아래로 쌓임).

### 6-5. 다시 생각 (2차)
- 라운드는 1차와 2차, 2회로 고정한다. 3차 이상은 이번 범위가 아니다.
- 교사가 "다시 생각" 버튼을 누르면 학생들이 다시 눈금을 고르고 이유를 쓴다. 규칙은 1차와 같다(이유 필수, 제출 후 잠금).
- 2차 화살표는 수직선 위쪽에 표시된다(위로 쌓임).
- 2차가 시작되면 화면에는 2차 화살표만 나온다. 1차 화살표는 숨겨진다.
- 교사가 "1차 보기" 버튼을 누르면 1차 화살표가 수직선 아래쪽에 나타나 위아래로 비교할 수 있다. 다시 누르면 사라지는 토글이다.

### 6-6. 이동 표시
- 2차를 제출한 학생의 이름 칩에 이동 표시가 붙는다.
  - 오른쪽으로 두 칸: "▶2"
  - 왼쪽으로 세 칸: "◀3"
  - 이동 없음: "유지"
- 좌우 방향은 수직선 양 끝 라벨과 맞춘다.
- 아직 2차를 제출하지 않은 학생의 칩에는 이동 표시가 없다.

### 6-7. 제출 상태 표시
- 이름 칩에 제출 전과 제출 후가 구분되어 보인다(칩 색 또는 체크 표시). 교사가 누가 아직 안 냈는지 바로 알 수 있어야 한다.

### 6-8. 이름 숨기기
- 교사 화면에 "이름 숨기기" 토글을 둔다. 켜면 칩과 화살표의 이름이 번호로 바뀐다.
- 번호는 학생이 입장한 순서대로 시스템이 매기고, 칩 순서와 같게 유지한다.
- 2차 개발의 의견 카드 화면에도 같은 토글이 적용된다.

## 7. 의견 카드와 반응 (2차 개발)

- 교사가 "다음"을 누르면 학생이 의견을 쓰는 단계로 넘어간다.
- 학생당 카드는 1장이다.
- 카드에는 입장할 때 쓴 이름이 붙는다. 이름 숨기기를 켜면 가려진다.
- 학생은 제출하면 교사 화면에만 모인다. 교사가 "공개"를 눌러야 학생 화면에 나타난다. 쓰는 즉시 공개되지 않는다.
- 공개는 카드 한 장씩, 또는 전체 한 번에 할 수 있다.
- 교사는 부적절한 카드를 숨기거나 삭제할 수 있다.
- 공개된 카드는 제출 순서대로 격자 형태로 쌓인다. 드래그 배치는 없다. 카드가 많아지면 아래로 스크롤된다.
- 학생은 다른 학생의 카드에 반응을 누를 수 있다. 댓글은 없다.

## 8. 워드클라우드 (2차 개발)

- 재료는 교사가 버튼으로 고른다: 의견 카드 글 또는 수직선 이유 글.
- 수직선 이유 글을 고르면 1차 이유, 2차 이유, 둘 합친 것 중에서 다시 고른다.
- 단어 묶기는 단순 처리다. 띄어쓰기 단위로 단어를 세고, 흔한 조사(이, 가, 을, 를, 은, 는 등)를 뒤에서 잘라 낸다.
- 한계: 형태소 분석이 아니라서 같은 단어가 일부 갈라지거나 조사가 아닌 글자가 잘릴 수 있다. 이 한계는 알고 가는 것으로 한다.
- 교사가 워드클라우드에서 단어를 눌러 제외할 수 있다.

## 9. 이번 범위에서 제외

- 3차 이상의 반복 라운드
- 화면 이미지(PNG) 저장
- 엑셀·CSV 내보내기
- 카드 드래그 배치, 카드 댓글
- 형태소 분석
- 학생 번호 입력, 자동 삭제
- 여러 교사가 동시에 쓰는 환경

## 10. 개발 지침

- 기능 하나를 끝낼 때마다 커밋하고 GitHub에 푸시한다.
- 1차 개발이 끝나면 멈추고 사용자에게 확인을 받은 뒤 2차 개발로 넘어간다.
- 학생 응답은 GitHub에 올리지 않는다.
- 학생 화면에서 다른 학생의 선택이 새어 나가지 않도록, 화면에서 가리는 데 그치지 말고 Firestore 보안 규칙으로도 막는다.
- 제출 버튼을 누르면 "이 위치로 제출할까요?" 확인 단계를 둔다(잠금 방식이라 실수 구제용).

## 11. 추정으로 채운 항목

사용자가 직접 정하지 않았고 작성 과정에서 붙인 내용이다. 다르면 바꿔야 한다.

- 학생 화면에는 숫자(-5~+5)를 보여주지 않고, 칸 위치와 양 끝 라벨만 보인다.
- 중복 참여자는 합치지 않고 삭제만 한다.
- 반응은 "좋아요" 하나이고, 자기 카드에는 누를 수 없으며, 한 카드에 학생당 한 번만 누를 수 있다.
- 방 삭제 외에 방 안의 참여자 개별 삭제를 허용한다.
- 학생은 로그인 없이 들어오므로, Firebase 익명 인증으로 기기를 구분하는 방식을 쓴다.
- "깃허브에 자동 저장"은 개발 중 코드의 자동 커밋·푸시를 뜻한다.
- 수직선 이유 글 워드클라우드의 1차/2차/합친 것 선택.
